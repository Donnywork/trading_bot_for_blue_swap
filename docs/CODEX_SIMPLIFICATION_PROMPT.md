On a fresh start, entries are paused in Simulation, or in Paper when running without a vault. Keep Paper and Simulation clearly labeled. Preserve the existing recovery path for recorded live state, with new entries paused.
2. **Choose simulation or live.** Give the dashboard an explicit **Simulation / Live (Sepolia)** control that works while the bot is running. Simulation uses the existing read-only contract simulation path. Live requires the operator to have already set `DRY_RUN=false` and the bot to pass the existing Sepolia, signer, vault, and risk checks. Require a fresh mode request after startup for new live trading. Pause new entries on a mode change and require a separate **Start Trading** action before they resume. 3. **Start or stop trading.** **Start Trading** allows new entries in the active mode when the existing guards pass. **Stop Trading** pauses new entries immediately when the bot processes the request. Keep monitoring, receipt follow-up, and exits for recorded inventory running. Preserve the existing explicit exit control.
4. **Update pool liquidity.** **Scan Pool Liquidity** submits the existing one-shot Phase 2 scan request for both configured pools. Show scan status and the block and time of the liquidity snapshot the bot is using. Keep scan acknowledgement durable across restarts and mode changes, and defer full scans while inventory is open.
